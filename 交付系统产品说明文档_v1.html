1需求背景与 V1 范围决策

交付体系 2.0 升级后，学员的 8 个高频提问（课程安排、预习资料、作业、批改、进度……）需要一个唯一真相源来回答。上一版说明文档（v1.0）按「全功能一步到位」设计，包含资料上传下载与作业提交批改。

为什么收窄是正确的 V1 要解决的问题只有一个：学员登录后能自己找到「下节课是什么、预习在哪、资料在哪」。这个问题不需要文件系统也不需要批改流。砍掉两者后，V1 开发量约减 40%，且邮件通道与移动端 UI 是无论如何都要做的基础——先做窄而对的，比做宽而慢的先上线。

被移出的功能不废弃，全部进入第 10 章分期路线的 V2：作业提交（链接式）与批改、资料站内上传下载、微信小程序端与微信授权登录。

2产品定位与目标

一句话定位：学员的课程唯一真相源（V1 为只读版）。课程结构、排期、预习、资料清单在系统里只存一份、只有这里是最新的；邮件只负责把人拉回来，不在邮件里承载内容。

V1 目标（三条，全部可验收）

  • 登录可用：学员用邮箱完成注册（含邮箱验证）与登录，全程手机浏览器可完成
  • 六问有答案：8 问中的 6 问（课程安排 / 预习 / 资料 / 下节课 / 进度 / 刷题入口）在系统内自助可答；作业、批改两问 V1 显示定义但交付走线下
  • 手机体验达标：375px 宽度下全部页面无横向滚动、单手可达核心操作，为小程序迁移不留设计债

4核心用户故事

「我买了课，最烦的是不知道下一节上什么、预习材料翻聊天记录翻半天。」——学员

用户访谈原话，2026-09

学员侧（V1 全部）

  • 作为学员，我可以用邮箱注册账号并收到验证邮件，激活后登录，不用记第 4 个密码之外的东西
  • 作为学员，我打开首页就看到下一节课（课名 / 时间 / 上课链接）和我的进度，不用问任何人
  • 作为学员，我可以在课程地图看到全部 4 个模块、15 节 1v1 与 27 讲录播的完整安排
  • 作为学员，我点开任何一节课能看到预习内容（三问预写 + 关键词）、资料清单（外链直达）、作业定义
  • 作为学员，我可以把预习标记为已读、把录播标记为已完成，让进度条真实前进
  • 作为学员，我能在上课前 2 天收到预习提醒邮件、在排期确定时收到确认邮件，邮件里只有一句话和链接，点开直达对应页面
  • 作为学员，我在「我的」页能看到账号信息、所在班期、通知邮箱，能退出登录

运营侧（V1 全部）

  • 作为运营，我给学员排课时只填「时间 + 上课链接」，保存后学员端 1 分钟内可见
  • 作为运营，我可以给某节课的学员批量发送预习提醒 / 上课确认邮件，并看到发送记录
  • 作为运营，我能在学员列表看到每个人的进度（已上课数、预习已读数），发现掉队的人
  • 作为运营，我能预览学员视角的课程地图，确认上架内容无误
明确不做（V1） 作业提交与批改流、资料上传下载与站内存储、微信 / 飞书消息推送、多讲师分权、录播观看进度自动采集（V1 学员手动标记）、支付与订单。这些在 10.1 分期表中各有归属版本。

6.1 账号与注册登录

账号主键 = 邮箱（与通知通道一致，V1 唯一登录方式）。流程：注册（邮箱 + 密码 + 姓名）→ 系统发验证邮件 → 点击链接激活 → 登录。登录态保持 14 天，过期自动回落登录页。

验收要点

  • 邮箱格式与密码强度（≥8 位，含字母数字）前端 + 后端双重校验
  • 验证邮件 60 秒内到达；激活链接一次性、24h 过期、过期可重发
  • 未激活账号登录时提示「请先查收验证邮件」并给重发入口
  • 连续 5 次密码错误锁定 10 分钟（提示走邮件）
  • 注册时由运营预先导入白名单（邮箱 → 班期），非白名单邮箱注册提示联系班主任

6.2 学习台（首页 tab）

学习台回答两件事：我在哪（进度）与下一步做什么（下一节课 + 待办）。自上而下：进度总览 → 下一节课卡 → 待办列表。

验收要点

  • 下一节课卡取「已排课且时间在未来」的最近一节；无排课时显示「待排期 · 联系班主任」占位
  • 进度数字 = 已上课 / 总课时（1v1 线）与已标记完成 / 总讲数（录播线），两条独立进度
  • 待办由系统规则生成：预习（T-2 已解锁未读）、录播（当前部分未完成）；无待办时显示鼓励文案
  • 上课链接按钮在开课前 30 分钟内高亮呼吸提示

6.3 课程地图（课表 tab）

全部课程结构的唯一展示位：4 模块可折叠，课时行显示代号、标题、状态与排期时间，当前位置高亮。结构数据 100% 来自《课时安排定版 v3》。

验收要点

  • 结构（模块 / 课时 / 代号 / 标题 / 类型）为后台数据驱动，非前端硬编码；Demo 线回归后追加课时卡前端零改动
  • 状态色语义：灰=未解锁/待排期、绿=已完成、高亮=当前（NOW）、蓝=预习已发
  • 录播课时行显示「已看 n / 总讲数」；点开显示该部分逐讲清单与完成标记
  • 模块折叠状态本地记忆（下次进入保持）

6.4 课时详情页（只读）

一节课的全部信息一页收口：上课信息卡（时间 + 链接）→ 预习 → 资料 → 作业。四个区块全部只读展示（V1 无提交无下载，资料走外部链接）。

验收要点

  • 预习区在 T-2 前 0 点起解锁，之前显示锁定态（时间 + 「预习将在 T-2 解锁」）；解锁由排期时间自动推导
  • 资料链接运营可换（换后学员端即时生效），外链域名不限制但展示完整 URL 防钓鱼
  • 「加日历」生成 .ics 或跳系统日历（iOS / Android 兼容）
  • 已上课的课时卡：预习/资料仍可看，上课信息卡变历史态（显示实际上课日期）
  • 录播课时卡：显示逐讲清单 + 每讲时长 + 完成标记开关 + 配套代码包外链（V1 视频链接即外部链接）

6.5 消息提醒（邮件通道）

V1 通知通道只有邮件。原则：邮件里只放一句话 + 一个直达链接，内容永远在系统里看（拉回机制，不承载内容）。

  • 所有邮件经同一 SMTP 服务发送，发件人显示统一品牌名（如「NiceOffer 班主任」）

  • 每封邮件含退订说明（合规），链接均带学员专属 token，免登录直达对应页面（有效期 7 天）
  • 运营后台可看到全部发送记录（收件人 / 类型 / 时间 / 状态）

6.6 运营后台（桌面端）

运营后台是内部工具，桌面优先，不进小程序。V1 四块：学员管理、排期管理、内容预览、邮件中心。排期管理是核心——同一课时卡在不同学员处独立排期（班期隔离的最小体现）。

验收要点

  • 排期保存后学员端学习台 / 课程地图 / 课时卡在 1 分钟内更新（接口实时，无缓存延迟）
  • 时间修改 > 1 天时自动发变更邮件；填链接为空则拦截「发预习邮件」并提示
  • 学员管理页：列表展示姓名（脱敏邮箱）、班期、进度（已上课 n/15、预习已读 n）、最后登录时间；支持筛选掉队（7 天未登录）
  • 邮件中心：发送记录表（收件人 / 类型 / 时间 / 状态），失败可一键重发
  • 运营账号独立入口（/admin），与学员端鉴权隔离，登录失败锁定策略同 6.1

7状态机与数据要点

V1 只有两条状态流（作业状态机已随范围收窄移至 V2）。状态由排期时间自动推导 + 学员轻操作驱动，学员端不出现「提交 / 批改」类状态。

1v1 课时状态流（每学员独立）

  1. 未解锁未排期 / 距上课 > 2 天
  2. 预习中T-2 0 点自动解锁 + 发邮件
  3. 待上课预习已读或上课日到
  4. 已上课运营标记完成（时间过 24h 自动兜底）

预习已读是学员动作（标记已读按钮），驱动待办消失与已读率统计；已上课驱动进度条前进。

录播状态流（每讲独立，学员手动标记）

  1. 未开始默认态
  2. 已完成学员点「标记完成」

9非功能需求

  • 移动端优先（最高优先级）：学员端全部页面以 375px 宽度为准设计验收（6.7 硬约束表）；核心路径（登录 → 看课表 → 看预习 → 点上课链接）在手机上单手可完成；不依赖 hover；目标微信小程序迁移零重构
  • 性能：4G 网络首屏 ≤ 2 秒；纯展示页无重前端计算；课时卡数据一次拉取本地缓存 + 下拉刷新
  • 邮件到达率：使用企业级 SMTP 服务；单用户单类型 24h 防重；失败自动重试 2 次并进运营失败列表；敏感词与垃圾邮件规则预检（主题不用感叹号 / 全大写）
  • 安全：密码 bcrypt 哈希；JWT 14 天过期 + 刷新；后台独立入口；学员邮箱在后台列表脱敏；邮件内链接带一次性直达 token（7 天有效）；HTTPS 全站
  • 可维护：课程结构完全数据驱动（模块与课时卡为后台数据），课程调整（如 Demo 线回归）只加数据不改代码
  • 部署约束：域名备案完成前，部署于境外服务器（或免备案方案）+ HTTPS；备案完成、迁回国内后域名与数据不变化，学员无感
